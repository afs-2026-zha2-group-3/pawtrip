# 输入旅游总天数：短设计

## 意图与目标

在 `/cities` 先提供默认 1 天的 1–7 天步进器，合法后才允许选定目的地；将旅游总天数保存到当前浏览器标签页的 `sessionStorage`，并在景点页从左到右显示对应的第 1 天至第 N 天，供未来 US-09 行程生成按天安排。非法输入只提示，不污染已有合法值。

## 非目标与约束

- 不改后端、数据库、服务端 API 或账号数据。
- 不使用 `localStorage`，不做跨标签页或浏览器重启后的恢复。
- 不新增 US-09 行程生成页面或生成算法；US-09 后续读取本需求提供的状态模块和必填守卫。
- 复用现有 React、TanStack Router、Tailwind 与 shadcn/ui Base UI 约定。
- 天数状态与 `pawtrip.selectedDestination` 分开存储，避免登出/目的地清理逻辑相互影响；具体景点按天分配不在本阶段持久化。

## 方案比较

1. **仅 React 内存状态**：交互简单，但刷新后丢失，不适合当前会话恢复要求。
2. **`sessionStorage`（采用）**：符合用户指定，当前标签页刷新后保留、会话结束后清除；可由目的地页和未来 US-09 共享读取。需要处理 SSR 和存储异常。
3. **`localStorage`**：生命周期过长，可能把旧行程带到新会话，且不符合最新口径。

## 设计

- 新增聚焦的总天数状态模块，提供：读取合法值、保存 1–7 整数、清除/订阅（如页面需要同步）以及“是否已填写”的守卫判断。
- 建议存储键：`pawtrip.tripDuration`；值为可解析的整数文本。读取时必须验证 `Number.isInteger(value) && value >= 1 && value <= 7`。
- `/cities` 在目的地卡片前显示输入区，默认值为 1；步进器步长为 1、范围为 1–7，只有合法值时目的地「选定」按钮可用。边界点击不越界并显示提示；手工输入越界、小数、空值或非数字时，不写入存储，已有合法值保持不变。
- `/attractions` 读取合法总天数，从左到右显示对应的天数 Tabs，默认激活第 1 天；当前只提供按天浏览容器，不保存景点分配。
- 下游 US-09 通过共享读取函数获取 `number | null`；读取为空或非法时触发必填守卫，回到 `/cities` 的天数输入位置。该守卫的具体生成路由由 US-09 确定。
- 存储读写发生在客户端；SSR 首帧使用空值，挂载后恢复 `sessionStorage`，避免浏览器 API 在 SSR 中执行。

## 验证重点

- 1、7 可保存；2–6 可通过步进器增减。
- 0、8、负数、小数、非数字均出现提示且不覆盖已有合法值。
- 同一标签页刷新后恢复；新标签页/会话结束后不承诺恢复。
- 未填写时下游守卫提示并提供回到 `/cities` 天数输入处的导航目标。
- 仅前端文件与需求文档发生变更；`apps/server` 和数据库无改动。
