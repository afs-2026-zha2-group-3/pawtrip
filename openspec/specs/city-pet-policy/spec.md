# city-pet-policy Specification

## Purpose

面向计划携宠出行的用户，按目的地行政区提供当地养犬政策查询，并在宠物品种命中当地禁养名单时给出提醒，帮助用户在出发前更换目的地或提前准备材料。

## Requirements

### Requirement: 查询目的地的养犬政策

系统 SHALL 按行政区提供目的地养犬政策查询，返回政策条目、禁养犬种、可携带犬种、数据来源与更新时间。禁养犬种以可选犬种目录的犬种 id 关联保存；可携带犬种取自城市允许品种表，只从固定的可选犬种目录中选择。页面只展示禁养与可携带犬种的少量示例，MUST NOT 展示完整名单。政策内容为政府公开文件的人工摘录，仅收录已完成录入的城市。

#### Scenario: 查看已收录城市的政策
- **GIVEN** 目的地城市已收录养犬政策
- **WHEN** 用户查看该城市的政策
- **THEN** 系统展示该城市的政策条目，以及禁养犬种与可携带犬种的少量示例

#### Scenario: 展示犬种示例
- **GIVEN** 目的地城市已收录禁养犬种与可携带犬种
- **WHEN** 用户查看该城市的政策，无论当前品种是否命中禁养名单
- **THEN** 系统展示两类犬种的少量示例，并说明不是完整名单

#### Scenario: 可携带犬种未配置
- **GIVEN** 目的地城市已收录政策但后台尚未配置可携带犬种
- **WHEN** 用户查看该城市的政策
- **THEN** 系统展示"暂未收录可携带犬种"，MUST NOT 推断该城市允许携带

#### Scenario: 展示政策来源与时效
- **GIVEN** 用户查看已收录城市的政策
- **WHEN** 页面展示政策内容
- **THEN** 同时展示来源文件、更新月份和"以当地政府最新文件为准"的说明

### Requirement: 禁养犬种匹配与高亮提醒

系统 SHALL 使用统一政策匹配主体：存在激活行程且已绑定宠物时仅匹配该宠物，否则匹配当前用户全部宠物。每只宠物 SHALL 按其犬种 id 同时与目的地城市的禁养犬种关联和可携带犬种关联比较，并以宠物名 tag 展示结论。命中禁养关联时 SHALL 给出高亮提醒并说明可能后果；未命中禁养但在可携带关联中时 SHALL 明确告知未命中禁养名单。宠物没有可用犬种信息、品种 id 不在可选犬种目录，或品种既不在禁养关联也不在可携带关联时，系统 MUST NOT 给出命中或未命中的结论，仅展示通用政策。

#### Scenario: 品种命中禁养名单
- **GIVEN** 匹配主体的宠物档案包含犬种，且该犬种 id 与目的地城市的禁养犬种关联一致
- **WHEN** 用户查看该城市的政策
- **THEN** 系统显示该宠物的禁养 tag 和高亮提醒，指出命中的宠物与品种，并说明该城市政策不支持携带该宠物旅行

#### Scenario: 品种未命中禁养名单
- **GIVEN** 匹配主体的宠物档案包含犬种，且该犬种 id 在目的地城市的可携带犬种关联中、不在禁养关联中
- **WHEN** 用户查看该城市的政策
- **THEN** 系统明确提示该宠物未命中禁养名单，并说明仍需遵守其他规定

#### Scenario: 品种既不在禁养也不在可携带名单
- **GIVEN** 匹配主体的宠物档案包含犬种，但该犬种 id 既不在禁养关联也不在可携带关联中
- **WHEN** 用户查看该城市的政策
- **THEN** 该宠物 tag 显示无法判定，系统不做禁养判定并说明暂时无法判断

#### Scenario: 没有宠物档案
- **GIVEN** 用户没有添加宠物
- **WHEN** 用户查看该城市的政策
- **THEN** 系统不做禁养判定，并提示先完善宠物档案

#### Scenario: 宠物没有犬种信息
- **GIVEN** 匹配主体的宠物档案没有犬种信息
- **WHEN** 用户查看该城市的政策
- **THEN** 该宠物 tag 显示无法判定，系统不做禁养判定

#### Scenario: 品种不在可选犬种目录
- **GIVEN** 查询使用的犬种 id 不在可选犬种目录中
- **WHEN** 系统执行禁养匹配
- **THEN** 系统不做禁养判定，并说明暂时无法判断

#### Scenario: 禁养犬种关联为空
- **GIVEN** 目的地城市已收录政策但未配置禁养犬种关联
- **WHEN** 用户查看该城市的政策
- **THEN** 系统不得给出禁养命中结论；品种在可携带关联中时按未命中处理，否则不判定

#### Scenario: 存在激活行程时只判定激活宠物
- **GIVEN** 用户存在激活行程且已绑定一只宠物，同时还有其他宠物
- **WHEN** 用户查看该城市的政策
- **THEN** 系统只展示该激活宠物的匹配结论
- **AND** 不为其他宠物给出结论

### Requirement: 维护城市可携带犬种

管理员 SHALL 能从固定的犬种目录中为城市选择并保存可携带犬种。保存后，用户查询该城市政策时 MUST 返回并在页面展示最新列表。未授权用户 MUST NOT 调用维护能力。

#### Scenario: 管理员保存可携带犬种
- **GIVEN** 管理员在城市管理中选择一个城市并勾选可携带犬种
- **WHEN** 管理员保存
- **THEN** 系统保存城市与犬种的关联，用户查询该城市政策时返回这些犬种

#### Scenario: 清空可携带犬种
- **GIVEN** 管理员已为城市保存可携带犬种
- **WHEN** 管理员取消全部勾选并保存
- **THEN** 该城市的可携带犬种列表为空，用户页面显示"暂未收录可携带犬种"

#### Scenario: 非管理员访问维护能力
- **GIVEN** 当前用户不是管理员
- **WHEN** 用户尝试读取或保存城市可携带犬种
- **THEN** 系统拒绝访问

### Requirement: 政策未收录的提示

系统 SHALL 将未收录政策视为正常业务状态。查询未收录政策的城市时，系统 MUST NOT 返回错误，MUST 展示"暂无当地政策数据"的提示并说明覆盖范围。

#### Scenario: 查看未收录政策的城市
- **GIVEN** 目的地城市未收录养犬政策
- **WHEN** 用户查看该城市的政策
- **THEN** 系统展示"暂无当地政策数据"的提示
- **AND** 说明仅覆盖已收录政策的城市

#### Scenario: 仅有行政区记录但未录入政策
- **GIVEN** 某城市在行政区数据中存在，但没有录入过养犬政策
- **WHEN** 用户查看该城市的政策
- **THEN** 系统按未收录政策处理

### Requirement: 查询不存在的行政区

系统 SHALL 在查询不存在的行政区时返回未找到错误，MUST NOT 将其当作未收录政策的城市处理。

#### Scenario: 行政区不存在
- **GIVEN** 用户请求的行政区代码在系统中不存在
- **WHEN** 系统处理该查询
- **THEN** 系统返回未找到错误，并说明该行政区不存在
