# location-management Specification

## Purpose

为管理员提供 PawTrip 地点资料管理能力，结合高德 POI 搜索和本地数据库维护地点基础信息、景点游玩时间及照片数据，并通过分页表格和编辑弹窗完成操作。

## Requirements

### Requirement: 管理员地点管理页面
系统 SHALL 为管理员提供包含“所有地点”和“pawtrip地点”两个 Tab 的地点管理页面，并在两个表格中提供城市与地点类型筛选。

#### Scenario: 管理员打开地点管理页面
- **GIVEN** 当前用户是已认证的管理员
- **WHEN** 用户打开地点管理路由
- **THEN** 页面显示“所有地点”和“pawtrip地点”两个 Tab
- **AND** 页面提供城市与地点类型筛选

#### Scenario: 普通用户访问地点管理页面
- **GIVEN** 当前用户已认证但不是管理员
- **WHEN** 用户打开地点管理路由
- **THEN** 地点管理页面不显示
- **AND** 用户返回普通受保护页面

### Requirement: 城市树筛选数据
地点管理页面 SHALL 从系统数据库读取省份与城市两层行政区数据；直辖市等没有市级子节点的省级行政区 SHALL 作为可选叶节点显示。

#### Scenario: 显示省市层级
- **GIVEN** 页面请求城市筛选数据
- **WHEN** 后端返回行政区树
- **THEN** 前端显示省份及其城市子节点
- **AND** 不显示县、区或街道级节点
- **AND** 有子节点的省份默认收起，并可展开查看城市
- **AND** 有子节点的省份仅作为展开控件，不可作为区域筛选值

#### Scenario: 选择无市级子节点的省级行政区
- **GIVEN** 某省级行政区没有市级子节点
- **WHEN** 管理员选择该省级节点
- **THEN** 筛选以该省级行政区为查询范围

### Requirement: 地点类型选项
后端 SHALL 向地点管理页面提供地点类型分组及对应高德 typecode；首版 SHALL 提供“景点”分组并映射到 `110000`。

#### Scenario: 获取首版地点类型
- **GIVEN** 管理页面请求地点类型选项
- **WHEN** 后端返回类型分组
- **THEN** 前端可选择“景点”
- **AND** 搜索筛选使用对应的高德 typecode `110000`

### Requirement: 所有地点列表
“所有地点”表 SHALL 按城市、地点类型从高德分页读取基础 POI 数据，并按高德 POI ID 与系统数据库匹配。已保存的地点 MUST 保留在表中，显示已添加状态并禁用该表中的编辑操作。

#### Scenario: 展示高德地点及已保存状态
- **GIVEN** 管理员选择城市、地点类型并请求某一页
- **WHEN** 后端返回该页高德 POI 与数据库匹配结果
- **THEN** 表格显示高德当前页的全部 POI 基础信息
- **AND** 已存在于数据库的 POI 显示已添加状态
- **AND** 已添加地点的编辑操作被禁用

#### Scenario: 搜索页不隐藏已保存地点
- **GIVEN** 当前高德查询页同时包含已保存和未保存地点
- **WHEN** 表格渲染该页
- **THEN** 两类地点均显示
- **AND** 已保存地点不会因数据库匹配而从结果中移除

#### Scenario: 未选择城市时不查询所有地点
- **GIVEN** 管理员尚未选择城市或无子节点的省级叶节点
- **WHEN** 管理员打开“所有地点”表
- **THEN** 前端不请求高德地点列表
- **AND** 页面提示先选择城市

#### Scenario: 选择城市后可以翻阅所有地点
- **GIVEN** 管理员已选择一个城市或省级叶节点，且结果超过一页
- **WHEN** 管理员选择下一页
- **THEN** 前端请求相同区域筛选条件下的下一页
- **AND** 表格显示对应页结果及正确分页状态

#### Scenario: 首次保存后立即更新所有地点行
- **GIVEN** 管理员从“所有地点”表保存一个尚未保存的 POI
- **WHEN** 保存请求成功并返回创建后的地点信息
- **THEN** 前端按 POI ID 直接更新当前页对应行的已保存状态
- **AND** 该行立即显示已存在于“pawtrip地点”的视觉提示并禁用编辑
- **AND** 不需要重新请求“所有地点”列表才能显示该状态

#### Scenario: 高德搜索分页上限
- **GIVEN** 当前高德查询的结果超过 200 条
- **WHEN** 管理员翻阅“所有地点”表
- **THEN** 表格遵循高德每页最多 25 条、同一查询最多获取 200 条的限制
- **AND** 不请求超出该查询可获取范围的页面

### Requirement: pawtrip地点列表
“pawtrip地点”表 SHALL 仅从系统数据库分页读取已保存额外信息的地点，并支持城市和地点类型筛选。

#### Scenario: 查询已保存地点
- **GIVEN** 数据库中存在已补充额外信息的地点
- **WHEN** 管理员打开“pawtrip地点”表并请求某页
- **THEN** 表格仅显示数据库中已保存的地点
- **AND** 返回结果包含分页信息

#### Scenario: 已保存地点列表不调用高德
- **GIVEN** 管理员打开“pawtrip地点”表或其地点编辑弹窗
- **WHEN** 前端读取列表或详情
- **THEN** 后端从数据库返回已保存信息
- **AND** 不为读取列表或详情调用高德 POI API

### Requirement: 地点分页查询
“所有地点”和“pawtrip地点”两个表格 SHALL 提供服务端分页；查询条件或页码改变时 SHALL 请求对应页数据。

#### Scenario: 切换表格页码
- **GIVEN** 管理员在任一地点表中选择另一页
- **WHEN** 前端执行该页查询
- **THEN** 请求包含当前筛选条件、页码和每页条数
- **AND** 表格展示对应页结果及分页状态

#### Scenario: 编辑 Pawtrip 地点后就地更新
- **GIVEN** 管理员正在“pawtrip地点”分页表中编辑某个已保存地点
- **WHEN** 更新请求成功并返回更新后的地点信息
- **THEN** 前端直接更新当前表格行和详情数据，不重新请求列表
- **AND** 该行保持原页码、行位置和数据库排序
- **AND** 数据库列表的总条数与排序不因编辑而改变

### Requirement: 景点游玩时间
地点额外信息 SHALL 包含可选的最小与最大游玩时间，单位为小时且只能为整数；该编辑项仅对“景点”类型显示和生效。

#### Scenario: 编辑未保存景点
- **GIVEN** 管理员编辑“所有地点”中的未保存景点
- **WHEN** 编辑弹窗打开
- **THEN** 弹窗展示 POI 基础信息和最小、最大游玩时间输入项
- **AND** 不展示尚未保存的 `business` 或照片详情

#### Scenario: 非景点不编辑游玩时间
- **GIVEN** POI 不属于“景点”类型分组
- **WHEN** 管理员编辑或保存该地点
- **THEN** 游玩时间字段不显示且不生效

#### Scenario: 游玩时间可为空且为整数小时
- **GIVEN** 管理员填写景点游玩时间
- **WHEN** 提交最小或最大游玩时间
- **THEN** 任一字段均可留空
- **AND** 已填写字段必须为整数小时
- **AND** 两个字段均填写时最小值不得大于最大值

### Requirement: 保存地点完整 POI 信息
管理员保存未添加额外信息的地点时，系统 SHALL 保存 POI 基础信息、游玩时间，以及高德 ID 详情 API 返回的全部 `business` 和 `photos` 数据。

#### Scenario: 首次保存景点
- **GIVEN** 管理员提交未保存 POI 的额外信息
- **WHEN** 后端获取该 POI 详情并完成保存
- **THEN** 系统保存 POI 基础数据、全部 `business` 数据、全部 `photos` 元数据及游玩时间
- **AND** 该 POI 出现在“pawtrip地点”表

#### Scenario: 保存扩展字段原始数据
- **GIVEN** 高德详情响应包含 `business` 或 `photos` 的可选字段
- **WHEN** 系统保存 POI 详情
- **THEN** 系统保留响应中这些对象的全部字段和值

### Requirement: 照片元数据与来源 URL 持久化
保存地点时系统 SHALL 持久化高德返回的照片元数据和来源 URL，且 MUST NOT 下载或持久化图片二进制。

#### Scenario: 保存地点时不下载图片
- **GIVEN** 高德 POI 详情包含照片元数据和来源 URL
- **WHEN** 管理员保存地点
- **THEN** 系统持久化照片元数据和来源 URL
- **AND** 后端不请求照片 URL，地点保存不依赖图片是否可用

#### Scenario: 保留照片扩展元数据
- **GIVEN** 高德照片对象包含 URL 及其他可选字段
- **WHEN** 系统保存 POI 详情
- **THEN** 系统保留照片对象中的字段和值供已保存地点详情读取
- **AND** 数据库不保存图片二进制

### Requirement: 前端通过来源 URL 直接显示图片
已保存地点详情 SHALL 提供照片来源 URL；管理页面 MUST 由浏览器直接加载 HTTP(S) 图片 URL，并 MUST NOT 通过 Pawtrip 图片二进制接口读取图片。

#### Scenario: 展示已保存地点的照片
- **GIVEN** 已保存地点详情包含有效的 HTTP(S) 照片 URL
- **WHEN** 管理员打开地点编辑弹窗
- **THEN** 页面直接通过该 URL 显示照片
- **AND** 图片请求不经过 Pawtrip 后端代理或二进制读取接口

#### Scenario: 图片来源不可用
- **GIVEN** 照片 URL 缺失、格式不受支持或浏览器无法加载该图片
- **WHEN** 管理员查看地点编辑弹窗
- **THEN** 页面显示图片占位状态
- **AND** 地点的其他详情和编辑操作仍可用

#### Scenario: 不提供图片获取或重试操作
- **GIVEN** 管理员打开已保存地点的编辑弹窗
- **WHEN** 页面显示照片
- **THEN** 页面不显示“获取图片”或重试按钮
- **AND** 前端不调用图片重试 API 或图片二进制读取 API

### Requirement: 行政区与地点分别保存宠物政策
系统 SHALL 在 `administrative_region` 和 `pawtrip_location` 表中分别保存宠物进入规则，包括每位游客最多可携带的宠物数量、单只宠物最大体重、牵引绳要求、疫苗证明要求、额外费用及预约要求。行政区政策适用于表中所有省级与城市级记录，包括以省级叶节点表示的直辖市。两层政策 MUST 相互独立，不得自动继承、复制或覆盖。

#### Scenario: 为已有记录添加规则字段
- **WHEN** 数据库迁移为已有行政区和地点增加宠物政策字段
- **THEN** 两张表中的记录均可独立保存六项规则
- **AND** 现有记录的未配置字段为 `NULL`
- **AND** 已有行政区与地点数据保持不变

#### Scenario: 行政区规则与地点规则相互独立
- **WHEN** 某行政区和其辖区内地点分别保存宠物政策
- **THEN** 更新行政区政策不会修改地点政策
- **AND** 地点未配置的字段保持 `NULL`，不从行政区政策推导

### Requirement: 宠物政策字段具有明确的空值、单位及计费语义
系统 SHALL 将 `NULL` 解释为未知或尚未配置；布尔字段的 `false` MUST 表示明确不要求，数值 `0` MUST 表示明确的零值。最多携带数量 SHALL 表示每位游客可携带的宠物只数；单只宠物最大体重 SHALL 以 kg 表示并支持小数；额外费用 SHALL 以人民币表示，按每只宠物每次到访计收。

#### Scenario: 区分未配置与明确值
- **WHEN** 宠物政策字段尚未采集，或已明确采集为不要求、零数量或零费用
- **THEN** 未采集字段保存为 `NULL`
- **AND** 明确不要求的布尔字段保存为 `false`
- **AND** 明确为零的数值字段保存为 `0`

#### Scenario: 保存重量与费用值
- **WHEN** 宠物政策记录了单只宠物最大体重及额外费用
- **THEN** 体重支持带小数的 kg 数值
- **AND** 费用表示每只宠物每次到访的人民币金额

### Requirement: 管理员编辑地点宠物政策
系统 SHALL 在管理员地点管理的“保存地点”和“pawtrip地点”两个现有弹窗中提供 6 项宠物政策的编辑能力，并 SHALL 适用于所有地点类型。表单 MUST 包含每位游客最多携带宠物数、单只宠物最大体重、牵引绳要求、疫苗证明要求、额外费用与预约要求。空输入 MUST 保存为 `NULL`；数值 `0` MUST 表示明确的零值；布尔字段 MUST 区分 `NULL`、`true`、`false`。额外费用 MUST 按人民币元输入且最多两位小数，保存为分；单只体重 MUST 最多两位小数；所有数值 MUST 非负。编辑弹窗 MUST 回填已保存值，并 MUST 允许把已配置字段清回未配置。修改地点政策 MUST NOT 修改行政区政策，也 MUST NOT 从行政区政策推导地点值。

#### Scenario: 新建地点填写政策
- **WHEN** 管理员在“保存地点”弹窗为未保存 POI 填写政策并保存
- **THEN** 地点保存成功
- **AND** 再次读取该地点时返回相同的 6 项政策值

#### Scenario: 编辑已保存地点并回填
- **WHEN** 管理员打开已有政策值的地点编辑弹窗
- **THEN** 6 项字段显示已保存值
- **WHEN** 管理员修改并保存
- **THEN** 再次打开弹窗显示修改后的值

#### Scenario: 清回未配置
- **WHEN** 管理员清空某项已配置政策并保存
- **THEN** 该字段保存为 `NULL`
- **AND** 重新打开弹窗时该字段为空

#### Scenario: 三态布尔
- **WHEN** 管理员为牵引绳、疫苗证明或预约要求选择“未配置 / 需要 / 不需要”
- **THEN** 分别保存为 `NULL` / `true` / `false`
- **AND** 重新打开弹窗时选中对应选项

#### Scenario: 非法数值被拒绝
- **WHEN** 管理员填写负数、非整数数量、或超过两位小数的体重/费用
- **THEN** 界面显示可读错误且不发起保存请求
- **AND** 直接向管理 API 提交非法值时返回 400，且不产生部分写入

#### Scenario: 所有地点类型可编辑
- **WHEN** 管理员编辑非景点类型的地点
- **THEN** 政策编辑区与保存操作仍然显示
- **AND** 游玩时间字段不显示

#### Scenario: 费用单位换算
- **WHEN** 管理员在额外费用输入框填写 `10.5` 元
- **THEN** 请求与持久化值为 `1050` 分
- **AND** 重新打开弹窗时显示 `10.5`

#### Scenario: 行政区政策不受影响
- **WHEN** 管理员保存某地点的政策
- **THEN** 该地点所属行政区的政策字段保持不变
- **AND** 地点未配置字段不从行政区政策推导

### Requirement: 管理 API 暴露地点宠物政策
管理 API SHALL 通过可选的 `petPolicies` 对象接收 6 个可空政策字段，并 SHALL 在地点详情响应的 `petPolicies` 对象中返回这些字段。创建地点时缺省 `petPolicies` MUST 将 6 项保存为 `NULL`。更新地点时缺省 `petPolicies` MUST 保持政策不变；携带 `petPolicies` 时 MUST 以对象内容整体替换 6 项，字段 `null` MUST 清空对应政策。地点列表响应 MUST 保持不变。非法数值 MUST 返回现有 400 错误，且 MUST NOT 产生部分写入。

#### Scenario: 创建时保存政策
- **WHEN** 创建请求包含 `petPolicies` 及 6 个字段
- **THEN** 地点保存后详情返回相同政策值

#### Scenario: 更新缺省不改
- **WHEN** 地点已有政策值且更新请求不包含 `petPolicies`
- **THEN** 6 项政策保持原值

#### Scenario: 更新整体替换与清空
- **WHEN** 更新请求包含 `petPolicies`
- **THEN** 6 项政策以请求内容整体替换
- **AND** 请求中为 `null` 的字段保存为未配置

#### Scenario: 详情返回政策
- **WHEN** 管理员读取已保存地点详情
- **THEN** 响应包含 `petPolicies` 对象
- **AND** 对象内的 6 个政策字段可为 `null`

#### Scenario: 非法政策值被拒绝
- **WHEN** 创建或更新请求包含负数、非整数数量或超范围小数值
- **THEN** 返回现有 400 错误
- **AND** 地点数据不发生部分写入

#### Scenario: 列表响应不变
- **WHEN** 管理员查询“pawtrip地点”列表
- **THEN** 列表响应结构与字段保持不变
- **AND** 不新增政策列或筛选条件
