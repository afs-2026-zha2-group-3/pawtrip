# Proposal

## Why

携宠出行时，飞机、高铁、火车、自驾对宠物的体重、容器、办理流程要求差异很大，用户需要在 12306 与各家航司官网之间反复确认，行前准备成本高。PawTrip 目前没有任何交通携宠规则内容（REQ-007 / US-05），本次把四种方式的规则集中成一张对比表，让用户在一处看清差异、决定出行方式。

## What Changes

- 新增前端交通携宠规则目录：四种交通方式（飞机 / 高铁 / 火车 / 自驾）的规则常量，必备「能否携带、体重上限、容器要求、办理流程概要」四个基础维度，并允许按规则需要新增列；飞机按国航 / 东航 / 南航 / 海航分行，规则含来源链接、来源标题与人工复核日期。规则全部写死在前端，不建表、不提供规则 API。
- 新增交通规则对比页 `/transport-rules`：以表格列表呈现四行 × 基础列（方式 + 四个维度），列可由列配置扩展（如体型限制、检疫证明）；「能否携带」用状态标识（可携带 / 有条件 / 不可），状态由数据字段驱动；飞机行通过下拉选择器切换航司；表格底部展示规则来源、复核状态、免责声明与"无站内订票"提示；无宠物档案时展示跳转档案录入页的按钮（指向预留路由，档案能力由 US-06 建立）。
- 顶部导航新增「交通规则」Tab（插在「城市浏览」之后、管理员 Tab 之前），Tab 选中状态与 `/transport-rules` 路由同步；`/cities` 页面保持现状。
- 本次不实现规则与宠物档案的对比判定（后端实现，随 US-06）；仅预留 `allowanceStatus`、`weightLimitKg`、`weightLimitNote` 与 `id` 字段及"不推荐"显示位置。

## Capabilities

### New Capabilities

- `transport-rules-catalog`: 前端交通携宠规则目录的数据契约——四种方式 × 四维度、飞机按航司分行、状态枚举、来源与复核日期字段，以及"复核日期为空不得发布"的发布约束。
- `transport-rules-comparison-page`: 登录守卫下的交通规则对比页面——四行表格展示、能否携带状态标识、飞机行航司下拉切换、底部来源/免责/无站内订票提示、无档案时的档案录入入口。

### Modified Capabilities

- `web-app-shell`: 顶部导航在「城市浏览」之后新增「交通规则」Tab，与 `/transport-rules` 路由及选中状态同步；该 Tab 对所有已登录用户可见（非管理员专属）。

## Impact

- 前端：新增规则常量模块（建议 `apps/web/src/data/transport-rules.ts`）、新增受保护路由 `apps/web/src/routes/_authenticated/transport-rules.tsx`、修改 `apps/web/src/routes/__root.tsx` 的 AppTabs（`activeTab` 与 `navigate` 同步扩展）；`routeTree.gen.ts` 由插件重新生成。
- 后端：无改动（无新表、无新接口、不改 Spring Security 放行名单）。
- 数据内容：规则由 12306 / 航司官网人工摘录，火车、海航、自驾条目当前待复核；`verifiedOn` 为空的条目不得合并入 main。
- 测试：新增 E2E 场景（登录 → 点击顶部「交通规则」→ 四行表格 → 航司下拉切换 → 未登录跳转 `/login`）；不新增后端接口测试。
- 依赖的需求：REQ-007（US-05）；后续依赖 US-06（宠物档案与后端对比判定）与 US-07（证明清单）消费本次预留契约。

## Effort Notes

- 规模：约 4 个前端文件（常量、路由页、`__root.tsx`、`routeTree.gen.ts` 生成）+ 1 个 E2E spec；无数据库迁移。
- 顺序：T1 规则常量（含待复核条目人工核实）→ T2 对比页 → T3 顶部 Tab 接入与 E2E；T1 与 T2 可并行，但合并前 T1 的复核必须完成。
- 单 Change 理由：三个任务同属一个用户可见能力（打开 Tab 即见对比表），拆成"常量包"将产生无用户可观察结果的水平技术切片。
