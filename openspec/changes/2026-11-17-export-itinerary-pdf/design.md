# Design

## Context

- US-48 已交付受登录保护的 `/itinerary`：`buildItinerary` 生成按天时间线，页面一次只渲染当前选中的 Day，政策默认折叠。
- 大交通规则已有唯一真源 `apps/web/src/data/transport-rules.ts`；`getRuleForMode` 返回某方式的代表规则，飞机按排序首位航司（国航）代表。
- 应用外框包括根 header 主导航、Trips/行程单共用的分段导航、Day Tabs 与行程面板 aside。
- 天气、应急、食宿与具体时间点尚无数据源。

## Goals / Non-Goals

**Goals:**

- PDF 与图片导出在行程单页面内容基础上补充详细信息：展开政策、附加大交通规则。
- 行程单页面视觉与交互不变（新增「导出 PDF」与「导出图片」按钮）。
- 不引入服务端 PDF 生成，不新增后端接口。
- 导出输出无应用外框，并尽量去除浏览器默认页眉页脚。

**Non-Goals:**

- 不改变行程单页面的常驻内容与布局。
- 不做离线缓存、站内分享与在线协作。
- 不接入天气、应急、食宿与具体时间点。
- 不保证所有浏览器都能抑制默认页眉页脚（取决于浏览器是否支持 CSS 页面边距盒）。

## Decisions

### D1：用浏览器打印生成 PDF，不引入 PDF 库

点击导出后调用 `window.print()`，用户在系统打印对话框选择「另存为 PDF」。相对引入 PDF 渲染库：零依赖、文本可选中、排版与页面一致；代价是依赖浏览器打印能力与用户一次确认操作。

### D2：打印期间渲染全部天并展开政策

页面默认只渲染选中 Day、政策折叠；导出时 `printing` 状态改为渲染 `itinerary.days` 全部天，并把每个 `<details>` 以 `open` 渲染，保证政策详情进入打印输出。连续两次 `requestAnimationFrame` 等待 React 提交后再调用打印。`afterprint` 复位，恢复当前 Day 与政策默认折叠；用户取消打印同样复位。打印态只影响导出过程，页面常规状态不变。

### D3：导出输出附加大交通携宠规则

新增导出专用规则卡：读取 `getRuleForMode(active.transportMode)`，展示方式、能否携带与摘要、体重/肩高限制、容器要求、办理流程、检疫证明、来源与复核日期。打印时使用 `hidden print:flex`，只在打印输出中出现；图片导出时以 `printOnly={false}` 直接渲染在同一离屏视图。行程单页面不新增常驻板块。`transportMode` 为空或 `getRuleForMode` 返回 `null` 时不渲染规则卡，其余内容照常导出。飞机规则因航司而异，卡片按代表航司展示并注明「以实际承运方最新规则为准」。

### D4：打印样式与页边距盒

- `@page { size: A4; margin: 14mm; }`，并在 `@page` 内定义 `@top-*`/`@bottom-*` 空内容页边距盒，抑制 Chrome 默认页眉页脚（URL、日期、页码），同时保留 14mm 页边距。
- `[data-print-hidden]` 隐藏行程面板；根 header、分段导航、Day Tabs、导出按钮使用 `print:hidden`。
- 地点卡片与规则卡 `print:break-inside-avoid`，减少跨页断裂；链接去色去下划线。
- 政策展开由 React `open` 属性完成，不再依赖 `details` 内部元素的 CSS 强制显示（Chrome 对折叠 `details` 的内容有独立隐藏机制）。

### D5：导出不改变行程数据

导出只切换展示状态，不写入 store 或后端；打印结束或取消后回到原 Day，行程数据与 URL 均不变。

### D6：图片导出复用同一导出视图

图片导出不另写一套内容，而是渲染与 PDF 相同的离屏导出视图：页头、大交通规则卡、全部天数（政策 `open`）与未排期。通过 `html-to-image@1.11.13` 的 `toBlob` 将整张视图渲染为一张 PNG；容器固定 1080px 宽，输出 `canvasWidth=1080`、`pixelRatio=1`，高度随内容增长。离屏容器放在视口外（`left: -20000px`），避免闪烁与布局占位；生成后通过临时 `<a download>` 触发下载，文件名 `{行程名}-行程单.png`。失败时捕获异常并展示「图片导出失败，请重试」，恢复按钮与页面状态。

替代方案：按天拆分文件（旧 story 口径）需要多次渲染与下载确认，且与 PDF 的整份导出视图不一致，因此不采用。

## Risks / Trade-offs

- **页眉页脚抑制依赖浏览器**：Chrome 131+ 支持 CSS 页面边距盒；不支持该特性的浏览器仍会打印默认页眉页脚，用户需在打印对话框手动关闭。
- **浏览器差异**：打印对话框的边距与背景色由用户与浏览器控制，产品无法完全统一。
- **分页**：卡片已避免卡内断裂，但超长规则仍可能跨页。
- **图片生成依赖 DOM 体积**：`html-to-image` 通过 SVG/foreignObject 渲染，超大 DOM 可能受 data URI 限制；当前单城市 7 天内行程可控。
- **图片无图片资源**：行程单不渲染远程图片，避免 canvas 污染；若后续加入封面图，需要处理 CORS。
- **内容不完整**：天气/应急/食宿缺失，导出内容受 US-12/US-13/US-16 制约。
- **飞机规则代表性**：行程只保存交通方式、不保存航司，飞机按代表航司展示并标注，可能与该用户实际航班不同。

## Migration Plan

纯前端展示与导出变更，无数据迁移。回滚删除导出按钮、`printing`/`exportingImage` 状态、导出视图与打印样式，并移除 `html-to-image` 依赖即可。

## Test Strategy

- E2E：stub `window.print` 计数；点击导出后断言调用一次且两天标题都渲染；导出态下不点击即可见政策字段（`8.5 kg`）；`emulateMedia({ media: "print" })` 后断言规则卡完整字段、行程/交通/提醒/未排期内容与负向板块，主导航、分段导航、Day Tabs、导出按钮与行程面板隐藏。
- 取消打印：向 `window` 派发 `afterprint`，断言回到单天、政策默认折叠、按钮重新可见、选中 Day 不变。
- 规则分支：高铁完整字段；飞机代表航司与无肩高；自驾无体重/肩高上限；无 `transportMode` 不渲染规则卡。
- 图片导出：点击「导出图片」后捕获一次下载，校验文件名、PNG 签名、宽度 1080px 与高度大于 1080px；失败分支通过覆写 `canvas.toBlob` 返回 `null`，断言提示与页面恢复。
- 单测：`imageFileName` 的清洗与空名称回退。
- 负向断言：常规页面不出现「大交通携宠规则」区块，政策保持折叠。
- 回归既有行程单 E2E 与前端单测。
- 浏览器默认页眉页脚抑制无法在 headless 中自动断言，需在真实打印预览中人工确认；在记录完成前该项保持 Pending，不记为 Pass。
