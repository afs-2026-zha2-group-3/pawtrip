# Proposal

## Why

携宠用户在出发前无法在一处确认目的地城市的养犬政策与禁养犬种，往往需要跨平台查找，甚至到当地才发现品种被禁养，只能临时改变计划或留下宠物。现有 `administrative_region` 只保存了 V7 引入的结构化入园字段（数量、体重、牵引、疫苗、费用、预约），没有政策文本、禁养犬种名单、来源与更新时间，无法支撑"了解当地养宠政策"这一需求。

需求来源：GitHub issue #14（US-04）、原型 dest-2 政策详情屏、living spec `location-management`。

## What Changes

- 新增城市养犬政策只读能力：按行政区查询政策条目、来源与更新时间；禁养犬种以可选犬种目录的犬种 id 关联保存，仅供匹配。
- 已收录政策的城市展示政策摘要，以及禁养犬种与可携带犬种的少量示例；当前宠物品种命中该城市禁养关联时给出高亮提醒，完整名单不在页面展示。
- 可携带犬种只从固定的可选犬种目录中选择，由后台管理系统维护；政策查询一并返回，未配置时显示"暂未收录可携带犬种"。
- 后台「城市管理」提供可携带犬种维护：选择城市、勾选固定目录中的品种并保存；非管理员不可访问。
- 未收录政策的城市展示"暂无当地政策数据"的空态提示，不按错误处理。
- 查询不存在的行政区时返回未找到错误，不按未收录政策处理。
- 政策展示同时包含来源文件、更新月份与"以当地政府最新文件为准"的说明（依据原型 dest-2）。
- 城市未配置禁养犬种关联时不给出命中或未命中的结论，避免把"名单未配置"误读为安全。
- 匹配同时使用禁养关联与可携带犬种表：命中禁养时提醒；在可携带名单中时提示未命中禁养；两者都不在、没有宠物或宠物没有犬种信息时不判定。
- 本期直接读取当前用户宠物档案中的犬种作为匹配输入（US-01 已交付）；档案不存在或没有犬种时不判定。
- 本变更不包含：目的地城市列表与筛选、目的地选定（US-47），宠物档案维护（US-01），政策文本与禁养名单的维护后台，以及站内订票。可携带犬种维护纳入本变更。

## Capabilities

### New Capabilities

- `city-pet-policy`: 按行政区提供养犬政策查询、禁养犬种匹配与政策未收录状态。

### Modified Capabilities

- 无。V7 已合并的结构化字段语义与 `location-management` 的既有要求保持不变；本变更只新增只读查询与展示能力。

## Impact

- 后端：新增只读政策查询接口、管理员维护城市可携带犬种接口，以及配套持久化数据（政策文本、禁养犬种关联、可携带犬种关联、来源、更新时间）及种子数据；不修改现有管理 API 与认证规则。
- 前端：新增政策详情路由与查询封装，读取宠物档案犬种并展示匹配结果；在城市浏览页（US-47）每个候选卡提供「查看政策」入口；补齐「城市管理」可携带犬种维护页，不修改应用外壳导航。
- 数据：以已归档的 V7 迁移为基础补充政策数据；禁养关联引用 `dog_breed` 目录，可携带品种复用城市允许品种表并由后台维护（迁移不写种子），历史行政区记录没有政策数据时保持"未收录"语义。
- 依赖：宠物档案（US-01）已包含 `dog_breed` 犬种关联，本变更直接复用；目的地列表（US-47）尚未实现，入口先在现有城市浏览页提供，不阻塞本变更交付。
- 契约：珠海通告 38 个品种中，当前可选犬种目录只能映射 8 个（如官方"比特斗牛梗犬"映射为目录"比特犬"）；其余 30 个品种无法从档案选中，按 G1 已确认的"词表外不判定"处理，后续按需扩目录。本变更不做运行时别名归一。
- 门禁：G1 对齐由 IO 与 SA 实名签署；2026-11-16 的 id 匹配与宠物档案接入属材料性变更，需在 G2 确认。本提案不代表 Delta Spec 已通过评审。
