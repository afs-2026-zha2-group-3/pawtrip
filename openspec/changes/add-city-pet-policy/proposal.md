# Proposal

## Why

携宠用户在出发前无法在一处确认目的地城市的养犬政策与禁养犬种，往往需要跨平台查找，甚至到当地才发现品种被禁养，只能临时改变计划或留下宠物。现有 `administrative_region` 只保存了 V7 引入的结构化入园字段（数量、体重、牵引、疫苗、费用、预约），没有政策文本、禁养犬种名单、来源与更新时间，无法支撑"了解当地养宠政策"这一需求。

需求来源：GitHub issue #14（US-04）、原型 dest-2 政策详情屏、living spec `location-management`。

## What Changes

- 新增城市养犬政策只读能力：按行政区查询政策条目、禁养犬种名单、来源与更新时间。
- 已收录政策的城市展示政策摘要；当前宠物品种命中该城市禁养名单时给出高亮提醒。
- 未收录政策的城市展示"暂无当地政策数据"的空态提示，不按错误处理。
- 查询不存在的行政区时返回未找到错误，不按未收录政策处理。
- 政策展示同时包含来源文件、更新月份与"以当地政府最新文件为准"的说明（依据原型 dest-2）。
- 禁养名单为空时不给出命中或未命中的结论，避免把"名单未配置"误读为安全。
- 匹配仅按品种名精确比较；品种为"其他"或没有品种信息时不判定禁养，仅展示通用政策。
- 本期使用可配置的演示品种作为匹配输入（不新增宠物档案持久化）；档案品种词表与本页珠海全称对齐后替换数据来源，对外行为不变。
- 本变更不包含：目的地城市列表与筛选、目的地选定（US-47），宠物档案维护（US-01），政策维护后台，以及站内订票。

## Capabilities

### New Capabilities

- `city-pet-policy`: 按行政区提供养犬政策查询、禁养犬种匹配与政策未收录状态。

### Modified Capabilities

- 无。V7 已合并的结构化字段语义与 `location-management` 的既有要求保持不变；本变更只新增只读查询与展示能力。

## Impact

- 后端：新增只读政策查询接口与配套持久化数据（政策文本、禁养名单、来源、更新时间）及种子数据；不修改现有管理 API 与认证规则。
- 前端：新增政策详情路由与查询封装；不修改现有应用外壳导航，入口由 US-47 落地后提供。
- 数据：以已归档的 V7 迁移为基础补充政策数据；历史行政区记录没有政策数据时保持"未收录"语义。
- 依赖：宠物档案（US-01）已包含品种字段，但 `dog_breed` 种子名称与本页珠海全称不一致；目的地列表（US-47）尚未实现。本期分别以可配置演示输入和直接路由访问解耦，不阻塞本变更交付。
- 契约：宠物档案的品种枚举必须使用珠海禁养名单全称（如"西藏獒犬"而非"藏獒"），否则精确匹配漏报；本变更不做别名归一。
- 门禁：G1 对齐由 IO 与 SA 实名签署，本提案不代表 Delta Spec 已通过评审。
