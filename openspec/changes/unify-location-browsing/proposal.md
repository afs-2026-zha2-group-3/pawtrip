# Proposal

## Why

用户端与管理端分别维护 Pawtrip 地点浏览接口：用户端只能按行程城市浏览景点，管理端则能按城市和类型查询全部已保存地点，造成查询能力与类型选项重复维护。将安全的只读地点列表和类型选项统一供所有登录用户使用，可在保留管理员写入与高德搜索权限的同时，让用户在激活行程城市内浏览并规划各类地点。

## What Changes

- 合并用户端景点列表与管理端 Pawtrip 已保存地点列表，提供一套需要登录的地点列表查询能力，供用户浏览页和管理页共同使用；支持区域、地点类型、分页和用户端现有宠物友好筛选。
- 将地点类型选项作为通用只读数据供用户端与管理端共用，不再为普通用户维护一份管理员专用的重复选项接口。
- 将用户端“景点浏览”扩展为“地点浏览”：查询范围仍固定为激活行程城市，不提供城市筛选；地点类型单选且默认“景点”，可切换住宿、宠物医院、宠物用品店、餐厅等已支持类型。
- 将现有“显示全部景点”筛选泛化为当前类型内的“显示全部地点”；所有地点类型均保留查看详情、逐宠物政策展示、“添加到行程”和“暂不排期”操作。
- AMap 候选搜索、地点创建与更新，以及管理编辑所需的原始 POI、商业信息和照片详情继续受管理员权限保护，不纳入通用地点浏览接口。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `trip-attractions`：将激活行程城市下的景点浏览扩展为地点浏览，增加地点类型筛选，并允许所有类型地点加入行程；列表改用共用地点查询能力。
- `location-management`：管理员“pawtrip地点”列表与地点类型选项改为复用通用只读接口；高德搜索和地点维护操作仍为管理员专属。

## Impact

- **后端 API**：统一已保存地点列表与通用类型选项的读取契约，并调整用户端和管理端的调用；保持 AMap 搜索及地点写入/管理详情接口的管理员权限边界。
- **后端实现**：涉及 `LocationQueryController`、`LocationQueryService`、`AdminLocationController`、`AdminLocationService` 与 `PawtripLocationRepository` 的查询复用，以及相应响应模型和安全配置。
- **前端**：涉及用户地点浏览页及其卡片/详情、管理端地点列表、两端查询模块和顶栏导航文案。
- **测试与文档**：更新用户列表、管理员已保存地点列表、类型选项、权限和行程加入行为的 API/UI 测试及相关规格/架构说明。
- **数据库与依赖**：不预期新增数据库迁移或依赖。
