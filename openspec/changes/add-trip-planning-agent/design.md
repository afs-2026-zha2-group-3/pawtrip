# Design

## Context

参见 `proposal.md` 的动机与范围。当前 `apps/web` 使用 TanStack Start、React Query 和 TanStack Store，但尚未集成 TanStack AI。登录后的 `_authenticated` 布局承载全局行程面板；`tripStore.active` 是现有编辑与自动保存上下文。未激活已保存行程可通过现有查询/更新函数读取和保存，但没有独立的前端编辑工作区。用户端地点列表接口只支持按区域查询景点；管理员地点列表不能供普通用户 Agent 使用。

## Goals / Non-Goals

**Goals:**

- 让 Agent 对话和规划服务可在有无激活行程时使用。
- 将 Agent 的规划目标与全局 `active` 状态分离，允许针对新行程、激活行程或未激活的本人行程构建待审核方案。
- Agent 仅访问 Pawtrip 已收录地点；地点读取保持普通用户权限边界。
- 所有行程变更在 UI 中明确展示并经用户确认后，复用现有创建/保存契约。

**Non-Goals:**

- 让模型直接写 trip API、数据库或地点库。
- 地图搜索、未收录地点创建、多城市/多宠物 trip、具体时间表、酒店预订或导航路线规划。
- 本次确定模型供应商或聊天记录跨会话持久化方案。

## Decisions

### TanStack AI 在 Start 服务端编排，浏览器承载 Pawtrip 工具

在 TanStack Start 服务端函数中运行 TanStack AI 对话循环；前端使用 TanStack AI React 聊天客户端处理流式对话。模型密钥只保留在服务端。采用该方式与现有 TypeScript/TanStack 栈一致；AgentScope 会额外引入 Python Agent 服务，对本次单个行程 Agent 并非必要。

工具定义采用明确 allowlist。对 Pawtrip 行程/宠物/地点的读取和行程应用操作由浏览器端工具执行，以复用同源请求、现有 Spring Session/CSRF 行为及前端状态。服务端负责对话和模型调用，不注册直接修改 Spring trip API 的服务端工具。

### 规划工作区与激活行程状态分离

规划工作区维护目标类型、目标 trip 快照和待审核方案，不把未激活 trip 写入 `tripStore.active`，也不因 Agent 操作改变 `activeTripId`。

- 新行程：用户确认后复用现有创建流程；按当前行为创建后激活。
- 激活行程：确认后通过一个前端批量应用动作更新计划，并增加保存 revision 以触发现有防抖自动保存。现有 `setPlan` 不增加 revision，不应直接作为 Agent 批量提交的唯一动作。
- 未激活已有行程：确认后从前端调用现有 `updateTrip` 语义，并刷新对应查询数据；不激活该行程。

不采用模型直接生成任意 API 请求，也不要求 Agent 逐条模拟鼠标点击。浏览器侧的类型化业务动作比 DOM 自动化更可靠，并能保留可见预览和用户确认。

### Pawtrip 地点目录查询保持只读且接口形态开放

Agent 的地点查找能力只针对 Pawtrip 已保存地点，覆盖所有地区和地点类别；不调用 AMap 候选搜索。现有 `/api/locations/attractions` 需要 `regionCode` 且仅包含景点，`/api/admin/locations` 受管理员权限保护，均不能直接满足此需求。

按用户要求，本设计不选定全量地点查询的 endpoint、筛选参数或响应结构。实现地点浏览前，必须先确定普通用户可用的只读目录查询契约及 capability 归属；浏览器工具只能调用确认后的 Pawtrip 数据接口。模型只能将查询结果中的真实地点 ID 纳入方案。

### 领域约束由 Pawtrip 代码验证

计划沿用既有 `TripPlan` v1 和 trip 服务校验。trip 只有一个城市和一个绑定宠物，天数范围为 1–7；既有行程城市/宠物不可更改。宠物规则以现有确定性匹配函数计算，Agent 可解释结果但不能自行决定友好性。跨城市地点不能加入当前单城市行程。

### 会话认证和工具输入按不可信边界处理

Agent 服务端入口必须验证现有登录会话，身份只能来自可信认证结果，不能接受客户端自报 user ID。列表和详情读取仍走当前用户可访问的接口；用户文本及地点内容均作为不可信数据传入模型。工具输入使用严格 schema，并在浏览器执行前重新校验目标、城市、天数与地点 ID；不提供通用 fetch、地图搜索或任意 trip ID 写入工具。

## Risks / Trade-offs

- **全量地点查询接口尚未确定** → 按 `proposal.md` 的开放问题，在实现地点浏览前先决定普通用户只读接口；不绕过授权使用管理员接口。
- **Start 与 Spring 使用的会话边界可能需要显式衔接** → 在暴露模型调用前验证服务端身份；同源浏览器工具继续通过现有 API 认证，禁止信任请求体里的用户 ID。
- **模型可能误匹配同名地点或违反排程偏好** → 展示真实候选与计划差异；含糊候选要求用户选择，应用前由 Pawtrip 代码校验。
- **完整行程更新沿用现有整量保存语义** → 预览基于已读取的目标行程；本次不改变后端 trip CRUD 或引入乐观锁。
- **宠物档案数据会进入模型上下文** → 只传当前规划所需字段与确定性政策结论，不传照片或无关档案信息。

## Migration Plan

本变更不需要数据库迁移，也不改变现有 trip API 契约。部署前配置模型供应商密钥并验证登录保护；若需要回滚，可隐藏 Agent 入口并关闭 Agent 服务端函数，现有行程浏览、创建和保存流程保持可用。
