# Proposal

## Why

后端需要把高德地点数据能力作为系统内部可复用的基础设施，而不是提前暴露成独立的 HTTP API。先接入 POI 2.0 关键词与周边搜索，同时建立可扩展的高德集成边界，为后续地点相关系统功能及其他高德 API 复用。

## What Changes

- 在后端增加高德 POI 2.0 关键词和周边搜索的内部集成能力，供应用层系统功能调用；本次不新增 Controller 或 `/api/pois/*` 路由。
- 每个 POI 条目保留高德返回的原始 JSON 结构；分页与数量等外层结果仅作为内部能力结果，不定义客户端响应契约。
- 高德 API Key 只从服务端配置读取；后端启动时自动从仓库根目录 `.env` 加载，且不依赖启动时的当前工作目录；进程环境变量优先于 `.env`，缺少 `.env` 不阻止启动，缺少 Key 时内部调用以类型化配置错误失败且不发起上游请求。
- 按应用端口与基础设施适配器分层组织代码；共用高德配置与 HTTP 传输，具体 API 按能力实现独立适配，避免单独建立顶层 `poi` 包或通用动态代理。
- 上游调用失败在内部集成边界转换为不泄露凭据和敏感请求数据的类型化错误。

不在本次范围内：客户端或 Controller、路线规划及其他高德 API 的具体实现、POI 数据落库或缓存、多边形/ID 搜索。

## Capabilities

### New Capabilities
- `backend-amap-poi-search`: 为系统内部功能提供高德 POI 2.0 关键词与周边搜索能力，并保留 POI 条目的原始结构。

### Modified Capabilities

无。

## Impact

- 后端 `apps/server`：新增应用层地点搜索端口与结果模型、高德 POI 集成适配器、共享 HTTP/配置基础设施；不新增 HTTP Controller 或公开路由。
- 配置：新增服务端 `AMAP_API_KEY` 配置，从根目录 `.env` 自动加载；支持用 `PAWTRIP_ENV_FILE` 指定外置 `.env` 文件，并提供不含真实凭据的 `.env.example` 与中文使用说明。
- 知识文档：更新后端分层架构和 Spring / 高德外部文档索引，为后续集成提供依据。
- 外部系统：高德 Web 服务 POI 2.0 `/v5/place/text` 与 `/v5/place/around`。
- 不需要数据库迁移；不实现客户端、路线规划 API 或其他高德 API。
