# 提案：将大交通方式保存到激活行程

## 为什么

交通规则页当前把选中的交通方式放在浏览器 `sessionStorage`，它既不属于具体行程，也无法随行程恢复。将选择关联到当前激活的 trip 后，用户可以在规则页选择大交通方式，并在行程面板中确认该行程所选方式。

## 变更内容

- 无激活 trip 时，交通规则页显示与景点浏览页一致的创建/激活行程空态及导航入口，不提供规则选择。
- 有激活 trip 时，保留交通方式单选；当前 trip 已保存的方式用于回显，选择后通过现有行程 Store 与自动保存流程持久化，不增加独立保存按钮，也不再使用 `sessionStorage` 保存选择。
- 行程面板顶部在 trip 已选择大交通方式后显示对应 tag。
- trip 数据、API 和数据库增加可空的大交通方式字段；新增数据库 migration，既有 trip 的该字段为空表示尚未选择。

## 能力范围

### 新增能力

无。

### 修改能力

- `transport-rules-comparison-page`：交通规则页依赖激活行程，单选值保存到该行程并在无激活行程时展示引导空态。
- `trip-context`：激活行程 Store 纳入大交通方式，并在行程面板顶部展示该值。
- `trip-planning`：trip 持久化模型、API 契约及数据库字段增加可空的大交通方式。

## 影响

- 前端交通规则页、trip Store/类型、自动保存逻辑、trip 面板，以及 trip API 查询与更新。
- 后端 trip 实体、请求/响应契约与数据库 migration。
- 更新上述三个 OpenSpec 能力的需求与场景；不引入服务端 active 状态，本功能以当前前端 Store 中的激活 trip 为操作对象。
