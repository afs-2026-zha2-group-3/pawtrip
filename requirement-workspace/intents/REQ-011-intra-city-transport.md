# REQ-011 意图捕获：途内交通推荐（打车/步行）

- 捕获日期：2026-11-17
- 来源：用户直接提供的 Story（含 Business Background / AC / 已决事项），并在同日对话中细化 MVP 口径

## 原始 Story（用户原文摘录）

> As a 计划携宠出行的用户
> I want 在行程中看到目的地城市内的途内交通安排（网约车/出租车、租车、地铁、公交）
> So that 我知道每天在市内怎么带宠物移动，不用到了当地才临时找车

用户细化口径（2026-11-17，原文）：

> 现在途内交通制作打车和步行 地铁公交等公共交通在前端显示不可携带宠物上车 用户在选择完景点后 计算景点打车或步行的预计价格和预计时间，并让用户选择途内交通方式 前端显示在用户打开每一天的行程查看那 在每两个景点中调用高德api计算 另外trip表，plan_json这个字段是json，存每天的安排

## Business Background

到达目的地后，市内移动主要靠网约车/出租车、租车、地铁或公交，而多数司机和运营方对携带宠物有额外要求。用户往往到了当地才发现打不到愿意接宠物的车。PawTrip 需要在按天行程中给出途内交通安排。

## System Limitation / Logic Currently

- 当前版本没有途内交通信息，行程中不包含市内交通安排。
- 现有行程工具不区分可携宠的途内交通方式。
- （代码事实）`plan_json` v1 已预留 `stop.toNext`（`walk`/`drive`/`transit`）并通过服务端校验与前端透传，但无设置 UI、无估算逻辑。

## Acceptance Criteria（原始）

- AC-1 按天展示途内交通：已生成按天行程，查看某天时展示当天的途内交通安排。
- AC-2 与当天地点关联：当天串联多个地点时，交通安排与当天串联的地点关联展示。
- AC-3 费用与时长参考：查看某段途内交通时，展示静态参考费用区间与预计时长。

## Assumptions / Open Questions（原始已决）

- 已决（2026-11-15）：途内交通覆盖网约车/出租车、租车、地铁、公交四类；可携宠判断依据各平台政策与政府公共交通政策，按 MVP 统一数据策略人工整理。
- 已决（2026-11-15）：展示静态参考费用区间与预计时长，不做实时计价。
- MVP 仅展示安排，不提供可携宠筛选（Release 2），也不提供站内叫车。

## 会话内已确认决策（2026-11-17）

1. MVP 范围按用户最新口径收窄：**打车 + 步行**两类参与估算与选择；**地铁/公交**仅静态提示「不可携带宠物上车」；**租车不在本次范围**（原始四类中的租车未获最新口径覆盖，记为 Out）。
2. 估算由 `apps/server` 代理调用高德路线规划 2.0（Key 仅服务端）；步行 `/v5/direction/walking`、打车复用驾车 `/v5/direction/driving` 的 `taxi_cost`。
3. 费用区间 = `taxi_cost` ±20%（用户批准）；步行费用为 0。
4. 展示位置：行程面板（TripPanel）按天视图中相邻两景点之间的交通段行。
5. 打开当天视图时按需计算；用户选择写入既有 `stop.toNext`（`drive`=打车、`walk`=步行），复用防抖保存。（原「估算结果不落库」已被决策 7 推翻）
6. 相邻景点相同：不调用高德、不计算价格与预估时间，仅在景点行下方一行小字提醒景点相同（2026-11-17 用户最新决策）。
7. **估算快照落库**（2026-11-17 用户最新决策，推翻「不落库」）：用户选择途内交通后，将方式 + 预估时间 + 预估价格存入 trip 表（`plan_json` 的 stop 新增可选 `toNextEstimate {durationMinutes, costLowYuan, costHighYuan}`，步行 0/0）；估算 API 本身仍不写库，快照由前端随既有防抖 PUT 写入。
8. 快照展示与兜底（2026-11-17 用户确认）：打开视图优先展示已存快照、不调高德；切换方式时重算并更新快照；选择时估算不可用 → 仅存方式、估算留空，后续估算成功补写；默认未显式选择仍不写库。
9. **打车携宠小字提示**（2026-11-17 用户最新决策）：每个当前方式为打车的交通段行内展示小字提示「部分平台提供宠物专车选项；普通网约车需司机同意，建议航空箱携带」（语义固定，措辞 P3 统一）；步行段不展示；展示位置用户确认为「每个打车段行内」（而非每天一条/全局一条）；默认按打车展示时同样展示。
10. **每天宠物政策对比提醒**（2026-11-17 用户最新决策，并入 REQ-011）：宠物档案（行程绑定宠物）须与当天已排期景点政策对比，在每天第一个景点行前小字提示（2026-11-17 用户位置修订，替换早前「每天最后一个景点行后」，内容规则不变）：a) 牵引绳——当天任一景点 `leashRequired=true` → 提示「当天需携带牵引绳」，档案 `hasLeash=false` 时加强「请自备」语义（用户确认聚合+档案对比）；b) 体型——当天任一景点设体重/肩高上限即视为有体型限制，与档案对比：**超限→警示「您的宠物超出XX景点限制（≤Xkg/≤Ycm）」；未超限不提示**（用户明确否决「未超限也展示限额」提案）；纯前端派生（复用面板既有景点政策缓存与宠物档案），不新增后端接口、不写库。
11. **大交通自驾联动**（2026-11-17 用户第 5 轮修订）：大交通 `transportMode=drive`（自驾）时，途内交通段行默认展示「驾车」，**仅显示预估时长、不显示费用**；派生默认不写库（与「默认打车仅 UI」同构）。每段提供「选择其他途内交通方式」下拉框（打车/步行），**驾车也可显式选择（含从打车/步行切回）；用户显式选择驾车则写库**（`toNext=self_drive` + 时长快照，费用 0/0 仅存不展示）；选打车/步行则按既有规则估算时间与价格并落库。自驾模式下隐藏每天公交/地铁不可携宠提示；携宠提示跟随段行实际方式（用户切为打车的段恢复展示，驾车/步行段不展示）；每天政策对比提醒保留不变。大交通为飞机/高铁/火车或未选择时完全按既有规则（默认打车）；切换大交通不破坏性改写已存选择，切回公共交通后恢复原保存选择展示。
