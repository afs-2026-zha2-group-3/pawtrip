# REQ-017 原始意图：行程携带清单与打包进度

> 来源：用户对话诉求（2026-11-18），用户故事 US-18「按档案生成清单」与 US-19「勾选打包完成进度」。编号 REQ-017（REQ-016 之后顺延）。分支 `feat/trip-packing-checklist`（自 main `cb8bb86` 拉取）。

## 用户原话（用户故事摘要）

### US-18 按档案生成清单

- **Business Background**：携宠出行物品比普通旅行更多，用户容易遗漏主粮、水碗、牵引绳、航空箱、尿垫等必需品。
- **System Limitation**：当前系统没有与行程关联的携带清单，用户只能靠记忆或通用清单准备。
- **Enhancement & Solution**：根据宠物档案与已确认行程生成一份携带清单，展示在行程单页面；使用固定的人工维护模板 + 档案/场景映射，不使用 AI；支持新增、删除、修改数量并持久化；档案变化时同步模板项，保留自定义项与勾选状态；分类包含证件、饮食、出行、健康、清洁；飞机场景增加航空箱与检疫/免疫证明；天数决定主粮份数（天数 × 每日份数 2）；无档案时引导先创建档案。
- **Acceptance Criteria**：AC-1 生成；AC-2 行程单展示与分类；AC-3 增删改持久化；AC-4 档案/场景同步并保留用户数据。

### US-19 勾选打包完成进度

- **Business Background**：清单生成后需要逐项确认是否已装箱，并在出发前看到整体打包进度。
- **System Limitation**：当前没有勾选态与进度统计，也没有跨设备同步。
- **Enhancement & Solution**：清单项可勾选/取消勾选；进度为已勾选物品行数 / 总物品行数；勾选态服务端持久化，同账号换设备仍保留；模板更新时保留勾选态；未生成清单时引导生成；全部勾选时展示完成态。
- **Acceptance Criteria**：AC-1 勾选/取消；AC-2 进度口径；AC-3 服务端持久化；AC-4 模板更新保留勾选；AC-5 空态与 100% 完成态。

## 需求澄清（2026-11-18 对话确认）

1. **入口与展示**：与「查看当天路线规划」一致，在行程单 Day 标签行右侧新增「携带清单」按钮，点击打开弹窗；行程单页面同时显示已完成物品数 / 总物品数。
2. **读取时自动跟随行程**：清单生成后，读取清单时自动按最新行程（大交通、天数）与宠物档案同步模板项，无需用户手动刷新模板。
3. **生成时机**：用户在弹窗内点击「生成携带清单」；生成前行程单进度显示「未生成」，不显示无意义的 0/0。
4. **每行程一份**：一个行程只有一份清单，重复生成请求幂等返回已有清单。
5. **分类与顺序**：固定 5 类、固定顺序（证件 → 饮食 → 出行 → 健康 → 清洁）；清单按分类分组展示。
6. **模板映射**：静态模板按宠物类型、体重/肩高、`hasLeash`、`hasVaccinationProof`、大交通方式、天数计算；不建模板表、不调用 AI 或外部服务。
7. **用户编辑边界**：模板项名称与分类随模板刷新，弹窗只允许修改模板项数量与勾选态；自定义项可修改名称、分类、数量；用户可删除任一物品。
8. **删除语义**：模板项被用户显式删除后不再复活；因场景变化（如大交通切换、档案变化）暂时不适用的模板项可隐藏，场景恢复时重新出现。
9. **数据保留**：模板同步保留自定义项、用户手动修改过的数量与已勾选状态；被重新激活的模板项默认未勾选。
10. **进度口径**：进度按当前可见物品行数统计，不按数量求和；无清单或未生成时不显示进度分数。
11. **无档案处理**：行程关联的宠物档案不存在时，生成返回 `PET_PROFILE_REQUIRED`，弹窗引导用户前往 `/paws` 创建档案。
12. **导出隔离**：携带清单弹窗不进入 PDF / 图片导出；行程单既有导出行为不变。

## 现状（代码证据，2026-11-18 调查）

- 行程单页面：`apps/web/src/routes/_authenticated/itinerary.tsx`，Day 标签行已有「查看当天路线规划」按钮，可复用同层布局与 Dialog 交互。
- 行程数据：激活行程 `active` 含 `id`、`petId`、`totalDays`、`startDate`、`transportMode`、`plan`；客户端由 `useActiveTrip` 提供。
- 宠物档案：`GET /api/pets` 返回类型、体重、肩高、`hasLeash`、`hasVaccinationProof`；档案保存后已有查询失效机制。
- 数据库：最新迁移为 `V28__add_pet_preferences_personality.sql`；本需求新增 V29 清单表。
- 后端错误：`ApiErrorCode` 已支持自定义业务码与 RFC 9457 Problem Details；需新增清单相关错误码。
- 清单能力：当前不存在清单表、领域、API 或前端页面。
- 测试先例：后端 `@SpringBootTest` + `@AutoConfigureMockMvc` 与 Flyway 迁移测试；前端 jsdom + Testing Library；E2E `e2e/itinerary.spec.ts` 以 `豆豆`、珠海、2 天行程种子。

## 用户已决口径（2026-11-18）

1. **入口**：行程单 Day 标签行右侧「携带清单」按钮 + 页面进度文案。
2. **展示**：弹窗形式，与路线规划弹窗一致；按分类分组。
3. **生成**：弹窗内手动生成，一次行程一份。
4. **模板**：静态代码模板；档案/场景映射；MVP 不做 AI。
5. **同步**：读取时按最新行程与档案同步；新增适用项、隐藏不适用项、刷新模板名称/分类/未覆盖数量。
6. **保留**：自定义项、手动数量、勾选状态。
7. **删除**：模板项删除为墓碑，不再复活；场景隐藏可重新出现。
8. **进度**：可见物品行勾选数 / 总行数；全部勾选展示完成态。
9. **无档案**：引导到 `/paws`。
10. **持久化**：服务端按账号持久化，跨设备一致。

## 方案取舍记录

- A（选定）行程单弹窗 + 服务端清单表 + 静态模板：与既有路线弹窗一致，满足跨设备与同步要求，无需新依赖。
- B 纯前端 localStorage：无法跨设备，且档案/行程同步与删除墓碑语义难以保证，放弃。
- C AI 生成清单：MVP 明确不做，模板可人工维护且结果可测，放弃。
- D 清单页独立路由：用户需离开行程单，入口与进度展示不一致，放弃。
