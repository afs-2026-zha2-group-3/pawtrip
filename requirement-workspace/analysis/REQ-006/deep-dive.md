**检索结论**：
- 四方式 × 四维度均可从公开渠道摘录；高铁/国航/东航/南航已拿到官方正文，数据质量高。
- 航司覆盖建议 MVP 取 **国航、东航、南航、海航** 四家（均有官方规则页；海航含"托运+客舱"两条记录，是唯一有成熟客舱宠物产品的主流航司）。南航"宠物进客舱"页面为 JS 渲染未抓取，MVP 先以托运规则入库，客舱条目待复核后补充（非阻塞）。
- 火车（普速）与自驾缺乏单一官方权威页，入库时 `verified` 标记必须经人工复核（95572/12306 口径），否则不发布。

## 2. 数据契约草案（粒度 / 字段 / 状态）

**概念：交通携宠规则（前端常量 `transport-rules-catalog`）**

- 粒度：一条记录 = 一个（交通方式 × 承运方 × 运输形态）。飞机按航司细分，同一航司"托运/客舱"可各一条；高铁/火车/自驾各一条通用规则（carrier 为空）。
- 权威存储：**前端 TS 常量模块**（`apps/web`，建议 `src/data/transport-rules.ts`，路径以 design 为准）；类型导出供页面引用与后续复用；不建数据库表、不写规则 API。
- 更新方式：代码变更（PR），合并前人工复核来源；无站内编辑。

| 字段（TS 常量字段） | 类型意图 | 说明 |
|---|---|---|
| id | 字面量/字符串 | 稳定标识（供后续 US-06/07 引用） |
| mode | 枚举 | `flight` / `high_speed_rail` / `train` / `drive` |
| carrierCode | 可空文本 | 航司二字码（CA/MU/CZ/HU）；非飞机为空 |
| carrierName | 可空文本 | 承运方名称；非飞机为空 |
| transportForm | 枚举 | `checked`（托运）/ `cabin`（客舱）/ `isolated_checked`（高铁隔离托运）/ `self`（自驾）；用于同航司多形态 |
| allowedSummary | 文本 | "能否携带"单元格正文（结论 + 关键限制：品种/健康/机型/航线） |
| allowanceStatus | 枚举 | "能否携带"状态标识数据源：`allowed`（可携带）/ `conditional`（有条件）/ `not_allowed`（不可）；标识只由本字段决定，不得在 UI 里按行写死 |
| allowanceNote | 可空文本 | 状态标识后的补充（如"导盲犬除外"、"按航司细分"），以弱化小字展示 |
| weightLimitKg | 可空数值 | 结构化体重上限（供 US-06 后端对比）；自驾缺省=无统一上限 |
| weightLimitNote | 可空文本 | 体重口径说明（如"含容器+食物水"）与附加体型限制（高铁肩高≤40cm/身长≤52cm） |
| containerRequirement | 文本 | "容器要求"维度摘要 |
| procedureSummary | 文本 | "办理流程概要"维度摘要 |
| extra | 可空字符串字典 | 扩展列取值（如 `heightLimitCm`、`quarantineNote`）；是否展示由前端列配置决定，基础四列不受影响 |
| sourceUrl | 文本 | 官方来源链接（展示可溯源） |
| sourceTitle | 文本 | 来源标题 |
| verifiedOn | 可空 ISO 日期文本 | 人工复核日期；空=未复核，不得合并 |
| sortOrder | 整数 | 展示排序 |

- 状态流转（MVP 简化）：`摘录（verifiedOn 空）→ 复核（填日期）→ PR 合并即生效`；更新规则 = 提交常量变更。
- 免责声明为全局固定文案"以承运方最新规则为准"（飞机场景"以航司最新规则为准"），常量不逐条存储。
- **US-06 对比契约**：对比逻辑在后端实现（档案表与档案存储随 US-06 建立，本需求不建）；本次只保证常量字段可支撑对比：`weightLimitKg` 结构化、`weightLimitNote` 承载体型附加限制、`id` 供后端接口引用；"不推荐"渲染位置约定为方式卡片/航司行级徽标（本次不实现）。后端获取规则阈值的具体方式（前端传参/后端留副本）留待 US-06 需求阶段定。
- **US-07 复用契约**：`procedureSummary` + `sourceUrl` 已含检疫证明等办证线索；复用形态（直接引常量或后续上移后端）留待 US-07 定。
